# Benchmark

Boss mode on versus off on a fresh fixture with hidden acceptance tests. Every run uses the real CLIs and the installed
Quota Boss (`node install.js` first), so it spends real quota. The folder is not part of the npm package.

```
node bench/run.js --host claude|codex --mode on|off --task small|medium|mixed [--model <id>] [--effort <level>] [--label <name>] [--n <k>] [--out <dir>]
```

- `small`: one function and its tests (5 hidden checks).
- `medium`: a task store, a report and a CLI with tests (18 hidden checks).
- `mixed`: `medium` plus four chores: a rename, JSDoc comments, two `package.json` fields and a README usage section
  (22 hidden checks). The chores give the boss trivial work it could hand down.

Defaults: `opus` for `--host claude`, `gpt-6.1-sol` at `medium` for `--host codex`, results in
`<tmp>/quota-boss-bench`. Each run appends one line to `results.jsonl` there: time, hidden and own test results, Claude
cost per model from the `claude -p` result, and every Codex session started in the fixture with its tokens and an
estimated USD price (list prices from [docs/MODELS.md](../docs/MODELS.md)).

`node bench/hidden-check.js <task> <folder>` runs the hidden checks alone.

Feedback the boss logs during a run is moved from `~/.claude/quota-boss/outcomes.jsonl` into the result line, so a
benchmark does not teach the router. That moves feedback from any other session that writes in the same minutes too, so
run no other boss sessions while benchmarking. The Claude arm starts `claude` directly; on Windows that needs the native
`claude.exe`, not only an npm `.cmd` shim, and the run stops without a result line when it cannot start.

One run per row shows direction only. Results so far are in [docs/BENCHMARKS.md](../docs/BENCHMARKS.md).

## Effort

```
node bench/effort.js --host claude|codex --model <id> [--efforts low,medium,high,xhigh] [--n 2] [--out <dir>]
node bench/effort.js --report [--out <dir>]
```

One fixed task (an exact scheduler in one file) per level, `--n` times, each checked by 11 hidden checks. Every run appends
its tokens, seconds and check result to `effort.jsonl`, and the report prints output and cost against `medium` per model.
The Claude runs use `--safe-mode` and only the Write tool, so the owner's hooks and plugins do not change the numbers. The
results are in the "Effort" section of [docs/MODELS.md](../docs/MODELS.md). Measuring all four levels twice on the four
Claude models used about half of a 5-hour window of a Claude subscription, most of it for `xhigh` on the two strongest models.

## Larger benchmark

The runner also accepts `--arm off|on|on:<profile>`; `--mode on|off` remains an alias. `on` uses balanced, and
`on:quality`, `on:balanced`, and `on:frugal` select the installed profile. The previous profile is restored in a
finally block using `set profile <name>`. Runs are sequential; do not run concurrent boss sessions.
`--reps 5` creates five fresh fixtures, with indices starting at `--n` (default 1). Existing run folders are rejected.
Use distinct labels or output directories for a new batch. Each result records its arm and run folder name.

Additional tasks (fixture files are generated by tasks.js):

- `bugfix`: three seeded collection bugs and an issue description; 9 hidden checks cover fixes and regressions.
- `refactor`: split statistics into selectFinite, totalOf and boundsOf, preserving summarize; 10 hidden checks.
- `docs`: README Overview/API/Examples and JSDoc parameters/returns; 7 structural, executable-example and behavior checks.

```sh
node bench/run.js --host codex --arm on:quality --task bugfix --reps 5 --out ./bench-results
node bench/review.js --out ./bench-results --judge claude --model opus --dry-run
node bench/report.js --out ./bench-results
node bench/report.js --out ./bench-results --json
```

Review defaults to dry run: packets and judge prompts are written in review-packets/. They contain the original task
prompt and the diff against the initial fixture commit, including untracked files. Managed instruction files,
quota-boss traces and identifying arm/label/model names are removed. review-map.json stores the shuffle seed and
packet-to-run mapping; keep this file away from judges. Reusing it preserves packet IDs. Generate review packets only
after all runs finish. To score programmatically, call exported review(out, {dryRun:false, judge, model, invoke});
invoke receives {judge,model,prompt} and returns {correctness,testQuality,codeQuality,sentence}. Each integer score is
1–10. Scores append to reviews.jsonl by packetId; if repeated, the report uses the latest review per packet.
`--run` scores the packets with the judge and spends quota; without it only packets are written. --judge and --model select the judge.

Reports group task × arm × host × model and show metric sample counts, means and deterministic percentile 95%
bootstrap intervals (2,000 resamples). Review score averages the three judge dimensions. Hidden pass rate is passed /
total checks, and own test count is pass + fail. Missing metrics show NA. Reviews are optional; a nonempty reviews file
requires its map. Cost ratios compare independent samples against off within the same task/host/model; zero baseline
means have no ratio. These are descriptive intervals for independent runs, not corrections for multiple comparisons.
Codex USD remains a token-price estimate, not a subscription invoice.

Suggested full plan: 6 tasks × 3 arms (off, on, on:quality) × 5 repetitions × 2 hosts = **180 runs**, followed by
180 blinded reviews if every run succeeds. Fix model/effort per host, schedule balanced batches across time, and keep
all failed-run outcomes in the analysis. **This spends real quota and must be agreed with the owner before execution.**
Only tooling and fake invocations should run during development; `node --test bench/*.test.js` never starts a paid CLI.
